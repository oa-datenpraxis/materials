Credentials in .Renviron speichern

Die .Renviron ist eine einfache Textdatei, die R beim Start automatisch einliest. Man kann dort Umgebungsvariablen im key-value-Format definieren, also nach dem Muster key = value. Sie eignet sich besonders für sensible Informationen wie API-Keys, aber auch für R-spezifische Einstellungen.

Warum sollte man nicht einfach einen API-Key ins Skript schreiben? Schreibt man den eigenen API-Key direkt ins Skript und lädt das Projekt dann z.B. auf GitHub hoch, kann jeder den Key sehen und ggf. auch nutzen. Die .Renviron-Datei liegt außerhalb des Projektordners und wird nicht mit hochgeladen, der Key bleibt also privat.

Wie funktioniert der Zugriff auf einen API-Key in der .Renviron-Datei? R lädt die .Renviron automatisch beim Start und macht alle darin definierten Variablen als Umgebungsvariablen verfügbar. Viele Pakete suchen automatisch im Hintergrund nach bestimmten Umgebungsvariablen und verwenden diese, ohne dass man z.B. den API-Key explizit einer Funktion übergeben muss. Man ruft lediglich die Funktion auf, und sie holt sich z.B. den API-Key selbst.

Zum Bearbeiten der .Renviron-Datei verwenden wir folgenden Befehl in der Console, den wir mit Enter ausführen:

file.edit("~/.Renviron")

Die .Renviron-Datei öffnet sich im Editor und wir fügen unseren API-Key in folgendem Format ein:

openalexR.apikey = YOUR_API_KEY

Anschließend speichern wir die .Renviron-Datei per Klick auf das Diskettensymbol und können das Fenster schließen.

Packages installieren und laden

Packages bieten Zusatzfunktionalitäten zu dem, was base R mitbringt. Sie können genutzt werden, nachdem sie einerseits installiert und andererseits geladen wurden. Installieren lädt das package einmalig herunter, laden macht das installierte package für die aktuelle R-Sitzung verfügbar. Packages müssen nur einmal installiert werden, jedoch jedes Mal neu geladen werden, wenn R gestartet wird, denn R lädt nicht automatisch alle installierten packages.

Zum Installieren von packages nutzen wir den install.packages Befehl. Wir können den Befehl entweder in einem Code Chunk ausführen, oder in der Console:

install.packages(c("openalexR","readr","tidyr","dplyr"))

Um packages zu laden wird in R der Befehl library(package_name) genutzt. Wir laden die zuvor installierten packages:

OpenAlex-API abfragen

Um die OpenAlex-API abzufragen nutzen wir die oa_fetch-Funktion aus dem openalexR package. Diese Funktion erstellt die Abfrage, sendet diese an die API und konvertiert das Ergebnis in ein tibble (eine Art data frame) bzw. data frame. Je nach Entität, die man abfragen möchte, gibt es unterschiedliche Filter, um die Suchergebnisse einzuschränken, siehe https://docs.ropensci.org/openalexR/articles/Filters.html.

Wir möchten Publikationsdaten abfragen, daher konzentrieren wir uns auf die works-Entität. Wir identifizieren Publikationen unserer Einrichtungen anhand ihrer ROR-ID. Paratexte (z.B. Titelseiten von Zeitschriften) und retracted Publikationen werden ausgeschlossen. Wir laden für dieses Notebook nur ausgewählte Felder, und zwar: DOI, Autor:innen-Angaben, Erscheinungsjahr, primärer Veröffentlichungsort (z.B. Zeitrschrift) und Publikationstyp. Das Ergebnis wird als tibble gespeichert (ein modernes data frame Format in R). Das paging = "cursor" sorgt dafür, dass auch große Ergebnismengen zuverlässig und effizient abgerufen werden.

Wir schränken auf einen relativ kurzen Veröffentlichungszeitraum ein, um die Ergebnismenge klein zu halten. Solltet ihr lokal Daten für ein ganzes Jahr abfragen wollen, so könnt ihr auch über den Filter publication_year = 2025 auf ein bestimmtes Jahr (hier bspw. 2025) eingrenzen. Wenn ihr keinen der Filter from_publication_date, to_publication_date, oder publication_year nutzt, könnt ihr alle Daten, die mit der ROR-ID verknüpft sind abfragen.

Der Pfeil (<-) ist in R der Zuweisungsoperator. Er weist das Ergebnis der rechten Seite der Variable auf der linken Seite zu. In diesem Fall wird das Ergebnis der Abfrage unter dem Namen df gespeichert. Dieses Objekt lässt sich dann über den Namen aufrufen.

df <- openalexR::oa_fetch(
  entity = "works",
  institutions.ror = "032000t02", #ROR-ID der Uni Ulm
  is_paratext = FALSE,
  is_retracted = FALSE,
  from_publication_date = "2025-10-01",
  to_publication_date = "2026-04-01",
  options = list(select = c("doi", "authorships","publication_year", "primary_location","type")),
  output = "tibble",
  paging = "cursor"
)

OA-Anteil

Um den prozentualen OA-Anteil zu berechnen, nutzen wir die summarise-Funktion. Diese Funktion fasst den gesamten Datensatz zu einer einzigen Zeile zusammen, indem sie für jede neu definierte Spalte eine Berechnung über alle Zeilen durchführt. Wir definieren dabei drei neue Spalten:

  • total_articles: die Gesamtanzahl aller Zeilen im Datensatz, berechnet mit der Funktion n() (eine Hilfsfunktion, die einfach die Anzahl der Zeilen zählt)
  • oa_articles: die Anzahl der OA-Publikationen, berechnet mit der Summenfunktion sum(is_oa, na.rm = TRUE). Da is_oa eine logische Spalte ist (also nur TRUE oder FALSE enthält), zählt sum() hier alle TRUE-Werte, weil R TRUE intern als 1 und FALSE als 0 behandelt. Das Argument na.rm = TRUE sorgt dafür, dass fehlende Werte (NA) bei der Berechnung ignoriert werden (ohne dieses Argument würde ein einziger fehlender Wert dazu führen, dass das gesamte Ergebnis NA ist)
  • oa_share: der OA-Anteil in Prozent, berechnet als oa_articles / total_articles * 100. round(..., 2) rundet das Ergebnis auf zwei Nachkommastellen
df_metrics |> 
  dplyr::summarise(
    total_articles = n(),
    oa_articles = sum(is_oa, na.rm = TRUE),
    oa_share = round(oa_articles / total_articles * 100, 2)
  )

Add-On: Wie viele first authors von der Einrichtung sind in den Daten verzeichnet

Die authorships-Spalte in unserem Datensatz ist eine sogenannte List-Column, d.h. jede Zelle enthält nicht einen einzelnen Wert, sondern eine ganze Tabelle mit allen Autor:innen-Angaben der jeweiligen Publikation (z.B. Name, Position, Affiliation).

Um die Autor:innen-Angaben auswerten zu können, müssen wir die List-Column zunächst “aufklappen”. Das erledigt die unnest-Funktion aus dem tidyr package. Die Funktion nimmt die verschachtelte Tabelle in jeder Zelle und fügt sie als neue Zeilen in den Datensatz ein – pro Autor:in einer Publikation entsteht also eine eigene Zeile, die verschiedenen Felder (Name, ID, etc.) werden als neue Spalten eingefügt. Anschließend filtern wir auf author_position == "first", um nur die Erstautor:innen zu behalten. Da eine Publikation mehrere Affiliationen haben kann, ist auch die affiliations-Spalte wieder eine List-Column, die wir erneut mit unnest aufklappen. Das Argument names_sep = "_" sorgt dafür, dass die neuen Spaltennamen mit dem Präfix affiliations_ beginnen und so klar von anderen Spalten unterscheidbar sind. Abschließend filtern wir auf die ROR-ID unserer Einrichtung, um nur Erstautor:innen zu behalten, die tatsächlich mit unserer Einrichtung affiliiert sind:

df_unnest <- df_metrics |> 
  tidyr::unnest(authorships) |> 
  dplyr::filter(author_position == "first") |> 
  tidyr::unnest(affiliations, names_sep = "_") |> 
  dplyr::filter(affiliations_ror == "https://ror.org/032000t02")

Speichern der Daten

Zum Schluss speichern wir noch unsere Daten im CSV-Format mit Hilfe der write_csv-Funktion. Wenn wir df_metrics als CSV speichern, gehen die verschachtelten Tabellen in der authorships-Spalte verloren, weil das CSV-Format keine List-Columns unterstützt (die Spalte wird dann als Text gespeichert und ist nicht mehr sinnvoll nutzbar). Wenn wir die Autor:inneninformationen nutzen wollen, speichern wir am besten df_unnest.

Der folgende Code speichert beide data frames in separate Dateien:

readr::write_csv(df_metrics, "data/df_metrics.csv")
readr::write_csv(df_unnest, "data/df_unnest.csv")
